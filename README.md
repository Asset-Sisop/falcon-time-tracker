# Falcon Time Tracker

Веб-приложение для учёта рабочего времени сотрудников. Проект подготовлен как тестовое задание для Falcon AI.

## Возможности

- создание и просмотр сотрудников;
- запуск таймера с названием задачи и необязательным описанием;
- остановка таймера и фиксация продолжительности сессии;
- запрет повторного активного таймера для одного сотрудника;
- история рабочих сессий с фильтрами по датам;
- сводный отчёт по сотрудникам за выбранный период;
- сохранение данных в PostgreSQL;
- REST API и интерактивная документация OpenAPI.

## Технологический стек

- Python 3.12
- FastAPI, Pydantic
- SQLAlchemy 2
- PostgreSQL 16
- HTML, CSS, Vanilla JavaScript
- Docker, Docker Compose
- pytest, FastAPI TestClient
- GitHub Actions (тесты и сборка Docker-образа)

## Быстрый запуск через Docker Compose

Требования: Docker Engine и Docker Compose plugin.

1. Клонируйте репозиторий:

   ```bash
   git clone https://github.com/Asset-Sisop/falcon-time-tracker.git
   cd falcon-time-tracker
   ```

2. Создайте файл окружения:

   ```bash
   cp .env.example .env
   ```

3. Установите в `.env` собственный надёжный пароль PostgreSQL (не используйте пароль из примеров):

   ```dotenv
   POSTGRES_PASSWORD=replace-with-a-long-random-password
   APP_PORT=8088
   ```

4. Соберите и запустите сервисы:

   ```bash
   docker compose up -d --build
   ```

5. Откройте приложение:

   - Web UI: http://localhost:8088/
   - Health check: http://localhost:8088/health
   - OpenAPI: http://localhost:8088/docs

Остановка без удаления данных:

```bash
docker compose down
```

Данные PostgreSQL хранятся в именованном Docker volume `falcon_time_tracker_data`. Не используйте `docker compose down -v`, если требуется сохранить данные.

## Локальный запуск без Docker

Требуется Python 3.12+. По умолчанию приложение использует SQLite в файле `time_tracker.db`.

```bash
python -m venv .venv
# Linux/macOS:
source .venv/bin/activate
# Windows PowerShell:
# .venv\\Scripts\\Activate.ps1

pip install -r requirements.txt
uvicorn app.main:app --reload
```

Откройте http://127.0.0.1:8000/.

Для подключения PostgreSQL задайте переменную окружения `DATABASE_URL`, например:

```bash
DATABASE_URL='postgresql+psycopg://user:password@localhost:5432/falcon_time_tracker'
```

## Тестирование

Установка зависимостей и запуск тестов:

```bash
pip install -r requirements.txt
python -m pytest -q
```

Набор тестов покрывает:

- создание сотрудника и получение списка;
- запуск и остановку таймера;
- отклонение повторного запуска активного таймера (HTTP 409);
- отклонение повторной остановки (HTTP 409);
- нулевые значения в отчёте без рабочих сессий;
- проверку некорректного диапазона дат;
- обработку несуществующего сотрудника (HTTP 404).

Результат актуального CI запуска проверяйте во вкладке **Actions** репозитория. Не считайте тесты пройденными, пока последний workflow не завершился успешно.

## Основные API endpoints

| Метод | Endpoint | Назначение |
|---|---|---|
| GET | `/health` | Проверка доступности приложения |
| GET | `/api/summary` | Сводные счётчики |
| GET, POST | `/api/employees` | Список и создание сотрудников |
| DELETE | `/api/employees/{employee_id}` | Удаление сотрудника |
| POST | `/api/employees/{employee_id}/timer/start` | Запуск таймера |
| POST | `/api/sessions/{session_id}/stop` | Остановка таймера |
| GET | `/api/sessions` | История с фильтрами |
| GET | `/api/reports` | Отчёт за период |

Интерактивная документация API доступна по адресу `/docs`.

## Бизнес-правила и технические решения

- Для одного сотрудника допускается не более одной активной рабочей сессии.
- Ограничение обеспечивается проверкой в API и уникальным частичным индексом БД для активных сессий.
- Повторный запуск активного таймера возвращает HTTP 409.
- Повторная остановка завершённой сессии возвращает HTTP 409.
- Время хранится в UTC; клиентский интерфейс отображает локальное время браузера.
- Отчёт рассчитывает пересечение сессий с выбранным периодом; активная сессия учитывается до текущего момента.
- PostgreSQL используется в Docker Compose; SQLite — для локального упрощённого запуска и тестовой среды.

## Использование AI-инструментов

При подготовке проекта использовался ChatGPT (GPT-6) как вспомогательный инструмент для проектирования структуры, подготовки отдельных фрагментов кода, тестовых сценариев, Docker-конфигурации и документации. Итоговые решения и проверка работоспособности должны оцениваться по исходному коду, автоматическим тестам и запущенному приложению.

Примеры задач/промптов, использованных как ориентир:

- «Спроектируй минимальное FastAPI-приложение для учёта рабочего времени сотрудников с PostgreSQL и SQLAlchemy».
- «Реализуй правило: у одного сотрудника может быть только один активный таймер; предусмотрите защиту от конкурентного повторного запуска».
- «Подготовь pytest-тесты для запуска/остановки таймера, повторного запуска и пустого отчёта».
- «Подготовь Docker Compose для приложения FastAPI и PostgreSQL с постоянным хранением данных».

AI использовался как ассистент разработки, а не как замена тестированию и проверке результата человеком.

## Ограничения демонстрационной версии

- В проекте нет аутентификации и разграничения ролей: не размещайте демо в открытом интернете с реальными персональными данными.
- Для публичной демонстрации используйте тестовые данные, HTTPS и ограничение доступа на уровне reverse proxy или VPN.
- Перед промышленным использованием необходимы миграции БД (например, Alembic), резервное копирование, аутентификация, авторизация, аудит действий и мониторинг.
